# Content Strategy and Briefs

Use for editorial strategy, content briefs, writing, refreshes, pruning, and cannibalization.

## Page Decision

Before drafting, decide whether to create, refresh, merge, redirect, keep, or remove. Check existing site coverage and intent overlap. A new page requires a distinct user job, SERP pattern, locale/product need, or information architecture role.

## Content Brief Contract

Include only fields useful to the writer:

- page purpose, audience state, primary conversion, and target intent
- primary query plus supporting questions/entities tied to sections
- recommended title, H1, slug, and meta description as editable proposals
- outline with the question each section answers and required evidence/examples
- information-gain plan: original data, demonstration, expert input, calculation, comparison, template, or first-hand evidence
- internal links in and out, with source/target page and contextual anchor direction
- trust requirements: author qualifications, citations, dates, disclosures, product/testing methodology
- media/table/schema opportunities when genuinely supported
- acceptance criteria and items explicitly out of scope

Do not prescribe arbitrary word count or keyword density. Estimate depth from the user task, topic complexity, and competitive evidence.

## Writing and Refreshing

- Answer the main question early, then progress from decision-critical information to detail.
- Use verifiable specifics and label uncertainty. For YMYL topics, browse current authoritative sources.
- Demonstrate experience only when real evidence exists; never fabricate testing, customers, quotes, credentials, or results.
- Write natural headings that describe sections. Avoid repetitive keyword variants and generic filler.
- Preserve valuable rankings, backlinks, URLs, and conversion elements during refreshes unless evidence supports a change.
- For decay diagnosis, compare query/page performance, intent drift, SERP changes, freshness needs, competing URLs, and technical changes before rewriting.

## Content Inventory Decisions

| Condition | Default action |
|---|---|
| Correct intent, outdated details | Refresh |
| Multiple pages serve same intent | Merge and redirect where appropriate |
| Valuable URL, weak execution | Improve in place |
| No demand or business role, no links/traffic | Consider removal after dependency check |
| Different intent despite similar terms | Keep separate and clarify targeting |

## Validation

Define pre/post checks: indexation, target queries, organic entrances, engaged sessions, assisted/direct conversions, internal-link coverage, and content accuracy review date. Avoid attributing movement to one edit without sufficient design or time.
